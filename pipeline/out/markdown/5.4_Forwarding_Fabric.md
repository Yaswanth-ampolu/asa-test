# 5.4 Forwarding Fabric

Forwarding Fabric
The Forwarding Fabric (FoFa) connects the DLLs of two nodes. It uses two DLP_TX and two DLP_RX as
shown in Figure 5-5. The FoFa logically belongs on the same layer as the ASEP, but it does not have
the same complexity and only buffers and routes containers unaltered.

Figure 5-5: Forwarding Fabric
The DLP_RX with the stream type “Data Forward” is always listed in the Demultiplexing Table 2(see
3.3.16)of nodeA. The DLP_TX with the stream type “Data Forward” is always listed in the Mapping
Table (see 3.3.13) of nodeB.
The connections of DLP_RX and DLP_TX with the stream type “Return OAM” have two caseseach.
DLP_RX on near-side from the root node: unused
DLP_RX on far-side from root node: hard connected to the DLP_TX of the OAM
DLP_TX on the near-side from the root node: listed in the Mapping Table of nodeB
DLP_TX on the far-side from the root node: hard connected to the DLP_RX of the OAM
See sections 5.2.3 and 5.3.2 for configurability of DLL Transmit Mapping and DLL Receive
Demultiplexing.
On the TX side of the Forwarding Fabric, the container headers in the DataForwardingQueue are
checked for the cases described in 5.4.1 and 5.4.2 for containers to be moved into the
OAMreturnQueue (see Figure 5-5 for an illustration). If neither of these conditions is evaluated TRUE,
each queue just operates as a first-in first-out buffer.
