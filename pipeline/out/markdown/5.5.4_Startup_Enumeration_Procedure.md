# 5.5.4 Startup Enumeration Procedure

5.5.4 Startup Enumeration Procedure
Enumeration, i.e. the distribution of addresses/nodeIDs in the SerDes Branch, is initiated by the root
node with Node-Discover (see 5.5.4.1) messages.
Node-Discover messages use extended headers for multi-cast, which do not occur in normal mode
OAM operation.
By means of Self-Announce (see 5.5.4.2) messages, the root node receives the information, how
many forwarding DLP are present (which implies how many nodes are implemented in the same
device).
After the root node receives a Self-Announce, it can address normal OAM messages explicitly to this
newnode and configure DLP_TX with ASEP stream type “Return OAM”and “Forward Data”(see
Table 7-1) for a slot in the mapper table (see 0) and an entry in the addressing table (see 3.3.6).
Deterministic one-by-one Forwarding of Node-Discover messages is ensured by the Data Link Layer
Receive Process (see 5.3). Far-side nodes can be directly addressed with OAM messages after the
near side Demultiplexing Table 2 (see 3.3.16) has been updated by the root node.
To the far-side node, the root can now send OAM messages to configure DLP_TX with ASEP stream
type “Forward Data” (seeTable 7-1) for a slot in the mapper table (see 0) and an entry in the
addressing table (see 3.3.6).
The enumeration is continued further out behind this far-side node by sending a Node-Discover
message with one targetID equal to the far-side nodeID and one targetID=0.
It is the responsibility of the root node to update the Demultiplexing Table 2 (see 3.3.16) in
previously enumerated nodes to list the nodeIDs of newly discovered nodes in the topology.
