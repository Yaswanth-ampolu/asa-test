# 5.5.3.7 LongAtom

5.5.3.7 LongAtom
There is no Address or Data for this command. This command signals (at the end of an OAM frame),
that the Write commands contained in this frame shall be buffered and only written, when a
LongAtomClose command is received. Each OAM frame before the LongAtomClose shall contain a
LongAtom CAD (at the end of an OAM frame).
Byte Bit(s) Name | Description
n+1 7:5 | reserved
n+1 4:0 | LongAtom OAM frame first frame of each LongAtom starts with 0, each
counter | successive frame of same LongAtom increments
the counter by 1
Table 5-12: LongAtom Command Address-Data
Between LongAtom and LongAtomClose, only Write commands are allowed. The maximum number
of consecutive LongAtom marked OAM frames are is limited to 31. No non-LongAtom OAM frames
containing CADs are allowed to be inserted between LongAtom and LongAtomClose (it is allowed to
intersperse empty OAM frames, containing just the OAM header, between LongAtom and
LongAtomClose). The 32ndframe must contain a LongAtomClose. If the LongAtomClose is not
received in the 32ndframe or one OAM frame up to the LongAtomClose was corrupted or is missing,
the Leaf must respond with all WriteAck = “Write fail”.
INFORMATIVE: This limit allows the atomic programming of the Mapper table including some
headroom through the upstream channel.
