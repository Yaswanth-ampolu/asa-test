The eDP ASEP builds on the VESA defined lane byte order mapping (including zero padding), see
[asep_dp_01] section 2.2.1.3. Komma characters are only transmitted once per occurrence
(regardless of the number of lanes coded), but VB-ID, Mvid and Maud are transmitted duplicated 4
times to fulfill VESA specification (see [asep_dp_01] Figure 2-12).
In the case of DSC, Compressed Data is being transmitted instead of Data Symbols (see [asep_dp_01]
section 2.8.4.4).
In the case of HDCP, "... in SST mode, all data symbols (including video data, secondary data and
dummy symbols) must be encrypted and K-codes must not be encrypted." (see [asep_dp_03],
section 3.1).
This means, the Komma Symbols are present as delimiters of data in all supported scenarios and are
therefore used as start and end markers of eDP ASEP packets.
When no HDCP is used, Stuffed Data Symbols between FS and FE can be decided to be dropped (not
encapsulated). Valid data of consecutive Transfer Units is then transmitted combined in one Main
Link ASEP packet, i.e. one video line.
The mandatory presence of the DP FEC for DSC compressed streams is to provide an error-correcting
capability for a data format, where individual bit errors can affect entire slices instead of single pixels.
The ASA physical layer FEC provides at least the same integrity protection and applies to all data.
HDCP on top of a DSC compressed stream is also an option. Since the HDCP cipher does not advance
in cycles carrying DP FEC control codes, the integrity of the encrypted data stream is given, see
[asep_dp_01] section 3.5.1.5.1.
The eDP ASEP packet for the AUX encapsulates one transaction per packet.
