# 6.4.4.5 Link Key Installation

6.4.4.5 Link Key Installation
The Root ECU consists of a Software (Root SW) and an ASA chip (Root Device).
The following procedure shall run on every link key installation process (that is when installing link
keys in all devices).
On Startup, both Key Slots (0 and 1) will undergo this process, on LK installation due to IV overflow
(KeyEx.report_status_LK, 0x81 with inactivated key slot) only the affected Key Slot will undergo this
process:
•
The Root Node shall request all PCNs of the devices, LKs need to be installed into.
•
The Root Node may request the UUID of all devices, if not stored.
•
The Root ECU shall generate the LKs and Salts:
o LKs shall be unique per link.
o Salts shall be unique per device and “KeyEx.install_LKs_encrypted”message.
•
The Root Node shall initialize its “KeyEx AEAD Invocation Counter” used for creating the IV of
outgoing KeyEx messages with 1.
•
The Root Node shall initialize its Salt used for creating the IV of outgoing KeyEx messages
with a random number.
•
The Root Node shall construct the IV for all outgoing messages based on the rules in section
6.4.1.4.
•
The Root Node shall install the LKs and Salts into the devices using the
“KeyEx.install_LKs_encrypted”message (see section 6.4.3.12 for details).
•
A Device shall check the incoming “KeyEx.install_LKs_encrypted” messages at least like this:
o Device shall check IV:
▪ KeyEx bit shall be 1, if not drop message and return status “Authentication failed
(0x11)”.
▪ Direction bit shall be 0 (Root to Device), if not drop message and return
“Authentication failed (0x11)”.
▪ Salt shall be the same for all KeyEx message in this power cycle, if not drop
message and return status “Authentication failed (0x11)”.
▪ Power Cycle Counter shall be the same for all KeyEx message in this power cycle,
if not drop message and return status “Authentication failed (0x11)”.
▪ The “KeyEx AEAD Invocation Counter” shall be larger than the previously received
value (receive counter initialized with 0). If this is not the case, drop and return
status “Authentication failed (0x11)”.
o Device shall check that the UUID matches the devices UUID. If not drop message and
return status “Wrong UUID (0x12)”.
o Device shall check the ICV.
o Device shall decrypt LKs and Salts.
o Device shall install LKs and Salts in the respective Key Slot.
o Device shall startup/unblock Link Layer Protection.
o Device shall update IV:
▪ If no KeyEx primitive received in power cycle, store Power Cycle Counter and
update receive IV counter to value.
▪ Set IV to received value.
o Device shall only generate a proof as answer (that is including IV and ICV), if status is 0
(OK):
▪ Generate IV based on section 6.4.1.4.
▪ Generate ICV based on section 6.4.1.6.
•
The Root Nodeshall check the response of the “KeyEx.install_LKs_encrypted” at least like
this:
o Root Node shall check IV, if present:
▪ Check that IV is increasing.
o Root Node shall check ICV, if present.
▪ Check the ICV using KeyEx bit = 1, Direction = 1 (upstream).
▪ Check the ICV based on installed Salt and Key.
o Root Node shall use status.
