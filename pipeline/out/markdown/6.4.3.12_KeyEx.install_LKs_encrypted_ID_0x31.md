6.4.3.12KeyEx.install_LKs_encrypted (ID: 0x31)
This primitive is used to install the Link Keys and Salts for them.
The ID of this primitive shall be 0x31.
This function shall be executable multiple times.
The IV and ICV shall only be present, if the Status is OK (0x00).
The device shall check, if the DK_0 was already written and abort with an error (0x40: Device Key
Part 0 missing), if this is NOT the case.
The device shall check, if the DK_1 was already written and abort with an error (0x41: Device Key
Part 1 missing.), if this is NOT the case.
The device shall check, if the BK was already written and abort with an error (0x42: Binding Key
missing), if this is NOT the case.
The device shall generate the IV based on the construction rules in section 6.4.1.4 using the freshly
installed salt of the first LK.
The device shall generate the ICV based on the construction rules in section 6.4.1.6.
If no key slot is active (e.g. after startup), the first key slot holding a key shall be activated.
If both key slots per ASA Node are written with the same function call, key slot 0 shall be activated
and key slot 1 shall be in ready state.
With installing a new LK in a key slot, the AEAD Invocation Counters are set as detailed in section
6.3.3.1.
The LKs_Salts has the following format:
•
Number [uint8]–the number of keys/salts installed.
•
Size_Keys [uint8]–the number of bytes per key. Typically, 16 for AES-128 or 32 for AES-256.
•
Size_Salts [uint8]–the number of bytes per salt. Always 4 for AES.
•
Reserved [uint8]–set to 0 and ignored on receive.
•
Array of Key-Salt-Combinations (Number of times):
o NodeID-KeySlot-Combination (1 byte)
▪ NodeID [7…3], Bitmask 0b11111000
▪ Reserved [2…1], Bitmask 0b00000110, shall be all 0 on TX and ignored on RX
▪ KeySlot [0], Bitmask 0b00000001
o Key (Size_Keys bytes).
o Salt (Size_Salts bytes), use bits [29:0] to install as Salt.
