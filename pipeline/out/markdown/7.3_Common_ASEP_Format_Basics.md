# 7.3 Common ASEP Format Basics

ASA Application Stream Encapsulation Protocol (ASEP)
ASA Application Stream Encapsulation Protocol (ASEP) defines the format, in which application data
is provided to the transmitting data link layer over the DLP_TX.
There is a multitude of stream types in the ASA Application Stream Encapsulation Protocol (ASEP).
Each defines one or more ASEP packet types including header and value field(s).
The Application Stream Encapsulator (ASE) acts as a transmitter on a DLP_TX whereas the Application
Stream Decapsulator (ASD) acts as a receiver on a DLP_RX. Each ASE and ASD on a specific Data Link
Layer Port supports only a single ASEP (see 3.5.1.2).
INFORMATIVE: A possible communication between an ASE and ASD in the same node for the
construction of an ASEP transceiver for bidirectional protocols is up to the implementer.
Application Stream Encapsulator
The ASE converts application stream data units into an ASEP format, where it has to handle header,
payload and footer generation as well as fragmentation into Data Link Layer Containers.
The ASE communicates with the Data Link Layer via the primitives defined in 5.6.1.
For a specific timeout dependent on the stream type andapplication, the ASE shall indicate a “data
starve event”, when expected application data units are not being received, in the register 3.6.2.
Application Stream Decapsulator
The ASD converts an ASEP format into application data units. It has to execute the reassembly of
fragmented ASEP frames as well as handle errors. Reassembly errors resulting in verifiably corrupt
application data units have to be recorded in 3.7.1.
The ASD communicates with the Data Link Layer via the primitives defined in 5.7.1.

There is common format per ASEP packet, which unifies the stream identification and time stamping.

for each format. The ASEP stream type codes are also used to identify DLP_TX/DLP_RX purpose (see
3.5.1.2).
