# 6.2 Keys and IDs

Security Entity
The existence of the Security Entity is optional.
Normative References for Security:
NIST FIPS PUB 197: Advanced Encryption Standard (AES)
NIST Special Publication 800-38D: Recommendation for Block Cipher Modes of Operation:
Galois/Counter Mode (GCM) and GMAC
Overview (Informational)
The Security functionality of this standard is made up by two high level components:
•
Key Exchange Entity–which is responsible for handling and exchanging keys. This
component is responsible for storing the keys securely. Key Exchange messages are
transported by the OAM channel.
•
Link Layer Security–which is responsible for protecting messages using keys provided by the
Key Exchange Entity. Protection means authentication and integrity protection. Encryption of
containers is an optional feature.
Keys and IDs
Achieving Security typically requires the use of cryptography, which in case requires cryptographic
keys. Additionally, the identification of devices needs to be defined as well.
Due to limitations regarding excess processing power on small sensors and cameras, only symmetric
cryptography is used. The symmetric keys are used for the AES algorithm (NIST, FIPS PUB 197:
Advanced Encryption Standard (AES)). AES will be used using the GCM or GMAC block mode (NIST,
Special Publication 800-38D: Recommendation for Block Cipher Modes of Operation: Galois/Counter
Mode (GCM) and GMAC).
Based on symmetric cryptography, the Key Hierarchy consists of 3 layers (top to bottom):
•
Device Keys (DK)–the top-level key of an ASA Device.
•
Binding Keys (BK)–the key binding an ASA Device to a vehicle.
•
Link Keys (LK)–session keys for the Link Layer Security, which are shared by adjacent
devices.
These keys are explained in the detail in the following sections.
The identity of an ASA device is based on a 128-bit number, called UUID in this document.
